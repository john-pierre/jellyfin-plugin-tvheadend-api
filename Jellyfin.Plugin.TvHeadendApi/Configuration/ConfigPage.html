📖 Recommended Setup Guide (TVHeadend + Jellyfin)

Follow these steps for the fastest channel switching (stream open < 3 seconds, even on first tune):

1. TVHeadend: Create a transcode profile

  • Click "Create jellyfin Profile" in the top action bar to auto-create an optimised profile in TVHeadend.
  • This creates a transcode profile named jellyfin that outputs MP4 / H.264 / AAC.
  • Alternatively, create the profile manually in TVHeadend: Configuration → Stream → Stream Profiles → Add profile-transcode, set Container = MPEG-TS or MP4, Video Codec = libx264, Audio Codec = AAC.

2. Plugin: Set Streaming Profile

  • In the Streaming section below, set the Streaming Profile to jellyfin.

3. Plugin: Playback Settings

  • Enable Direct Play ✅
  • Enable Direct Stream ✅
  • Enable Stream Probing ✅ — this allows Jellyfin to use the pre-created mediainfo cache immediately.
  • Enable Pre-create Probe Cache Files ✅ — the plugin writes cache files automatically so that even the very first tune to a channel is fast.

How it works

TVHeadend pre-transcodes every channel to a consistent format (H.264 + AAC). The plugin pre-creates Jellyfin's mediainfo cache files with matching stream metadata. When Jellyfin opens a channel it finds the cache, skips FFmpeg probing, and starts Direct Play immediately — resulting in channel switching under 3 seconds.

Probing means Jellyfin resolves the stream metadata it needs before playback starts, so it can decide whether Direct Play, remuxing, or transcoding is required. Recommended: ON when using a transcode profile with Pre-create Probe Cache Files enabled, because that gives Jellyfin the metadata it needs immediately and helps it start in Direct Play as fast as possible.
Important: Jellyfin has a hard-coded live TV delay of 3 seconds when it has to probe a stream. If Direct Play is not possible and Jellyfin falls back to transcoding, there is another hard-coded 3 second live TV startup delay on that path as well. Together with FFmpeg startup overhead, channel switching can easily end up around 8 seconds. With probing enabled and matching cache files already present, Jellyfin gets the data it needs right away and can stay on the fast Direct Play path.

💡 FFmpeg Settings (Optional)

To optimize stream analysis, you can configure Jellyfin's FFmpeg ProbeSize setting:

  • Go to Dashboard → Playback → FFmpeg
  • Set ProbeSize to 1000000 for faster stream analysis
  • Or set the environment variable JELLYFIN_FFmpeg__ProbeSize=1000000
When enabled, the plugin automatically creates mediainfo cache files for channels that don't have one yet. The files contain H.264 + AAC stream metadata matching the output of TVHeadend's "jellyfin" transcode profile. This makes even the very first tune to a channel fast by eliminating FFmpeg probing entirely.
⚠️ Only enable this when using a transcode profile that outputs MP4/H.264/AAC (e.g. the "jellyfin" profile). Do not enable with "pass" or other variable-output profiles — the cached metadata would not match the actual stream.
Stream buffer in milliseconds. 0 = Jellyfin default. Lower values reduce latency but may cause stuttering on slow connections.
Time FFmpeg spends analysing the stream before playback starts, in milliseconds. Default: 200 ms. This is the recommended value for fast startup. You can still set 0 to use the plugin's automatic fallback behaviour for older setups.
⚠️ Important: When Stream Probing is enabled, Jellyfin's core always overrides this value to 3000 ms for live streams. This plugin's value only takes effect reliably when probing is OFF and the plugin provides stream details from TVHeadend.
Note: -probesize is controlled by Jellyfin's global FFmpeg settings (Dashboard → Playback → FFmpeg) and cannot be changed from this plugin.
