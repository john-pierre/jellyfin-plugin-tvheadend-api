⚡ Fast Channel Switching Guide (< 3 seconds)

Goal: Switch channels in under 3 seconds — even on the very first tune. Follow these three steps:

①
Create the "jellyfin" transcode profile
Click "Create jellyfin Profile" above. This tells TVHeadend to output every channel as H.264 + AAC — a format Jellyfin can Direct Play without any conversion.
👤 Requires TVHeadend admin credentials to be configured in the Authentication section.
Manual alternative… In TVHeadend: Configuration → Stream → Stream Profiles → Add profile-transcode, set Container = MP4, Video = libx264, Audio = AAC.
②
Select the profile
In the Streaming section below, set Streaming Profile → jellyfin.
③
Enable fast playback settings
In Playback Behaviour below, enable: Direct Play ✅, Direct Stream ✅, Stream Probing ✅, Pre-create Probe Cache ✅.
How it works

TVHeadend transcodes every channel to a consistent format (H.264 + AAC). The plugin pre-creates Jellyfin's mediainfo cache files with matching metadata. When you switch channels, Jellyfin finds the cache instantly, skips FFmpeg probing, and starts Direct Play — channel switch in under 3 seconds.

Without this setup, Jellyfin probes the stream for 3 s, may fall back to transcoding (another 3 s delay), plus FFmpeg startup — easily 8+ seconds per switch.

Playback Behaviour

Controls how Jellyfin handles the incoming stream. Settings marked ⚡ directly affect channel switching speed.

Lets the client play the stream as-is without server-side processing. Fastest option — keep enabled.
Allows Jellyfin to change the container format without re-encoding. Fast fallback when Direct Play isn't possible.
Allows Jellyfin to transcode on-the-fly if a client can't play the original format. Slowest path — adds ~3 s extra delay. Only needed as last resort.
Ignore Decode Time Stamps. Can fix playback glitches with some MPEG-TS streams.
Jellyfin analyses stream metadata before playback to choose Direct Play, remux, or transcode. Keep enabled when using a transcode profile with pre-created cache files — Jellyfin gets the metadata instantly and stays on the fast Direct Play path.
Technical details… Without cached metadata, Jellyfin's core adds a hard-coded 3 s probe delay for live streams. If it then falls back to transcoding, there's another 3 s delay plus FFmpeg startup — totalling ~8 s. With matching cache files present, the probe resolves instantly.
Queries the selected TVHeadend streaming profile for its actual codec and container settings and pre-creates matching mediainfo cache files for all channels. This makes even the very first tune to a channel fast by skipping FFmpeg probing entirely.
Compares existing cache files with the currently selected TVHeadend streaming profile on every channel access. If the profile has changed (e.g. switched from "pass" to "jellyfin"), outdated cache files are automatically deleted and — when Pre-create Probe Cache is also enabled — replaced with correct ones.
Allows Jellyfin metadata plugins to enrich EPG entries (movies/series) using provider hints parsed from TVHeadend URIs. This can add better posters/logos/descriptions when plugins find a match.
Stream buffer in milliseconds. 0 = Jellyfin default. Lower values reduce latency but may cause stuttering on slow connections.
Time FFmpeg spends analysing the stream before playback, in milliseconds. Default: 200 ms (recommended for fast startup). Set 0 for automatic fallback behaviour.
Technical details… When Stream Probing is ON, Jellyfin's core overrides this to 3000 ms for live streams. This plugin's value only applies when probing is OFF. -probesize is controlled by Jellyfin's global FFmpeg settings (Dashboard → Playback → FFmpeg).
